# Calvin Chow — PM second brain case study

A static, responsive visual case study about grounding AI-assisted product decisions in evidence, improving through learnings governed by human-set approval rules, and extending the approach to a team.

## Preview

Open `index.html` in a browser, or serve this directory locally:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

No build step, external fonts, API keys, or backend are required. Aggregate page analytics use Umami Cloud.

## Edit

- `index.html`: narrative, diagrams, outcomes, and expandable context.
- `styles.css`: visual design, responsive layouts, reduced-motion support, and print styles.
- `script.js`: learning-loop step explanations.

## Publication

This folder is the publication boundary. Create a dedicated repository containing only these portfolio files. Never add the surrounding job-search workspace or source documents.

After content and design review, use a feature branch and pull request. GitHub Pages can serve the repository root from the `main` branch; relative asset paths support a project Pages URL. No custom domain is needed.

## Evidence and representation

Diagrams are reconstructions, and company/customer descriptions are generalized. The outcomes come from Calvin's confirmed account. The preparation-time comparison is approximate and observational; story cycle time is a broader team result with multiple contributors. Fewer repeated mistakes is qualitative. The scale-feature monetization strategy is a recommendation rather than an observed revenue outcome.

Selected recurring, less consequential themes became eligible for auto-approval only after explicit authorization and a month-plus of 100% historical manual approval. The confidence routes are a visual explanation, not an implemented approval engine. Core workflows and usage collection were live; value-aligned limits remain future direction.

## October 10, 2026 clarification

The four-dimension monitoring rubric is distinct from learning-approval history and quiz output testing. Fifteen manually scored anchors, historical replay, one-week parallel comparison, and source audits every two weeks are operating practices, without a measured quality uplift or model retraining claim. The corrected Claude planning-skill adoption is ~30% of R&D; the approximately eight-to-two-day result includes shared workflows and engineering collaboration, and is also described as ≈ $300K+ of team time, estimated — not ARR or upgrades. The 61% result remains a separate team outcome (~8 → ~3 days, multiple contributors). Certification outcomes include a contributed +4 point net revenue retention change (93% → 97%) quarter over quarter. `soul.md` and Calvin-bot describe generalized working context; no private context files are exposed.

## Portfolio page analytics

`analytics.js` loads Umami Cloud only on the published `calvin-chow-pm.github.io` domain and only in top-level pages. Both portfolios use one website ID, with per-page views, visits, and visitor estimates in the Umami dashboard. Local previews and embedded prototypes do not send analytics. Query strings and anchors are excluded from page grouping. Demo interaction events remain separate and are not sent to Umami. Tracking begins with installation; earlier traffic is unavailable.
